# Cloud Uploads

Headless Uploader supports direct-to-cloud uploads for AWS S3, Azure Blob Storage, and Google Cloud Storage. This approach is highly recommended for performance and scalability, as it bypasses your application server for the actual file transfer.

## The Secure Workflow

To maintain security, your client-side application should **never** contain your cloud provider's secret keys. Instead, use a "Signed URL" (or Shared Access Signature) pattern:

1.  **Request**: The client identifies a file to upload and requests an upload URL from your backend.
2.  **Authorize**: Your server verifies the user's permissions and session.
3.  **Sign**: Your server uses the Cloud SDK (AWS, Azure, or GCS) to generate a temporary, restricted URL.
4.  **Transfer**: The client uses the Headless Uploader Cloud Adapter to `PUT` the file directly to the cloud provider using that URL.

## 1. Server Setup

Your backend is responsible for generating the signed URL. Here is the general logic required for each provider:

### AWS S3 (Node.js Example)

<CodeBlock>
```javascript
import { S3Client, PutObjectCommand } from "@aws-sdk/client-s3";
import { getSignedUrl } from "@aws-sdk/s3-request-presigner";

const client = new S3Client({ region: "us-east-1" });

async function generatePresignedUrl(fileName, contentType) {
  const command = new PutObjectCommand({
    Bucket: "my-bucket",
    Key: fileName,
    ContentType: contentType,
  });

  // URL valid for 1 hour
  return await getSignedUrl(client, command, { expiresIn: 3600 });
}
```
</CodeBlock>

### Azure Blob Storage
Azure uses **Shared Access Signatures (SAS)**. Your server should generate a SAS URL with `Create` and `Write` permissions for the specific blob name.

### Google Cloud Storage
GCS uses **Signed URLs**. Use the `@google-cloud/storage` library's `getSignedUrl` method with `action: 'write'` and `version: 'v4'`.

## 2. CORS Configuration

Since the browser is sending a request from your domain to the cloud provider's domain, you **must** enable Cross-Origin Resource Sharing (CORS) on your bucket/container.

### Required CORS Settings:
*   **Allowed Origins**: Your application domain (e.g., `https://myapp.com`).
*   **Allowed Methods**: `PUT` (most cloud adapters use PUT).
*   **Allowed Headers**: `Content-Type` and any provider-specific headers (like `x-ms-blob-type` for Azure).
*   **Exposed Headers**: `ETag`.

## 3. Client Setup

On the client, you initialize the appropriate adapter and provide a function to fetch the URL from your server.

<CodeBlock>
```typescript
import { useUploader, createS3Adapter } from '@verbpatch/headless-uploader';

const uploader = useUploader({
  protocol: 'cloud',
  cloudAdapter: createS3Adapter({
    getUploadUrl: async (file) => {
      const response = await fetch('/api/get-presigned-url', {
        method: 'POST',
        body: JSON.stringify({ name: file.metadata.name, type: file.metadata.type })
      });
      const { url } = await response.json();
      return url;
    }
  }),
  onUploadSuccess: (file) => console.log('Uploaded!'),
});
```
</CodeBlock>

## Security Best Practices

*   **Short Expiration**: Set signed URLs to expire quickly (e.g., 5-15 minutes).
*   **Content-Type Validation**: Ensure the `ContentType` requested by the client matches what your server signs.
*   **File Name Sanitization**: Never trust the client-provided file name; generate a unique UUID or path on the server.
*   **Size Limits**: While cloud providers have their own limits, your server should validate the expected file size before signing the URL.
